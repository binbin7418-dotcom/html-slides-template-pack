SYSTEMS ONLINE STARDUST ENGINE · THE PROBLEM 01 — WHY

Fast hardware, slow pipeline

A modern GPU can finish a forward pass in single-digit milliseconds. Yet users waited seconds. The gap lives between the math: requests queued until a batch filled up, memory shuffled to make room for new sessions, and identical prompt prefixes recomputed on every single call.

We measured all three before writing any code. Queueing, fragmentation and redundant prefill accounted for 71% of end-to-end latency at peak. The model itself was never the bottleneck — the plumbing was.

SYSTEMS ONLINE STARDUST ENGINE · MECHANISMS 02 — HOW

Two of the three fixes

Prefix caching is the third; it gets its own deep-dive in the appendix.

MECH / 01

Continuous batching

Requests join and leave the batch at every token step, budgeted by tokens rather than request count.

  • GPU utilisation 41% → 78%
  • Long and short requests share a batch safely
  • Tail latency drops instead of rising
MECH / 02

Paged KV memory

The KV cache is allocated in pages and mapped on demand, like virtual memory for attention.

  • Fragmentation 23% → under 2%
  • Roughly a third more concurrent sessions per GPU
  • No pre-allocation guesswork per request
